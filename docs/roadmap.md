## 已完成（2026-10）

- `src/` 按 drivers、perception、localization、navigation、control、bringup 划分；ROS 2 包名与接口保留。
- 模式装配：`mapping-fastlio` 只起驱动、FAST-LIO 与必要 TF；导航组合才启用 FAR、CMU/MPPI、命令门控与跟随。
- 入口守卫：PCD 定位与通用 hardware mapping 明确拒绝，不静默切换；`mapping simulation` 要求外部时钟与传感器。
- FAST-LIVO2 保持独立 Noetic 构建入口与生命周期检查。
- 固件 `firmware/tr800_f407` 与本线共用同一实现，`COLCON_IGNORE` 阻止 colcon 扫描。

## 下一步（按优先级）

### P0 镜像与单场景

- 依次构建 production、PX4 工具链、SITL 与 SIM 镜像，记录镜像 ID 与源码 SHA。
- 跑单场景：`world:=maize_field robot:=husky_a200 headless:=true`，确认 `/clock`、TF、传感器与话题符合 [architecture.md](architecture.md)。
- 验收标准：镜像构建成功；单场景启动无遗留进程；导航入口读到真实传感器数据。

### P0 矩阵复跑

- 用 `run_matrix.py --runs 3` 跑九组合，与 2026-10-07 记录逐项对照。
- 验收标准：`matrix_results.json/csv` 完整；失败项保留原因与日志；不删失败记录、不放宽阈值。

### P1 地面导航

- 处理近场观测覆盖：VLP16 近场未知导致 MPPI 拒绝轨迹，历史诊断中 2 m 方形近域 100 格有 96 格未知。
- 处理数据新鲜度与初始化时序：落稳判定、桥接隔离、IMU 延迟。
- 验收标准：正常用例在不修改未知区、footprint 与新鲜度阈值的前提下通过；危险用例只有在同一轮正常用例成功后，其拒绝才算有效。

### P1 未接入能力

- 升级版 PCD 定位接入（当前入口直接拒绝）。
- 通用 hardware profile 的纯建图补齐标定配置。
- ROS 1 仿真适配的可行性结论；在此之前明确以 `main` 无仿真为准。

### P2 工程化

- CMU local Path 增加显式任务身份，收紧陈旧输入防护。
- FAST-LIVO2 生命周期与内存预算在目标机型上复测。
- 仿真矩阵加入入口级回归（进程清理、话题发现、参数解析）。
- 编码器第 2 路闭环在固件侧复测，与 main 共享同一结论。

## 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 地面仿真历史全失败 | 容易被误读为“仿真可用” | 交接时先讲结论，再给日志与图片 |
| 镜像与源码 SHA 绑定 | 增量验证不能代表全量重建 | 复跑时记录完整构建链与 digest |
| 近场观测与新鲜度 | 零速安全停机被当成通过 | 只用任务结果与接触/姿态指标判定 |
| 无 CI | 回归靠手工 | 每次改动跑相关 pytest、colcon test 与入口冒烟 |
| 协议跨三处 | 只改一端导致车不动 | 固件、ROS 2 驱动、ROS 1 驱动同改 |
