## 已完成（2026-10）

- `main` 承接原版 ROS 1 工程：18 个包，包名、算法源码、LICENSE/版权头与启动资源保留；生成目录、嵌套 Git 与大型地图/录包未进入源码。
- `upgrade/ros2` 保留升级成果（六域源码、地图与回环、FAR、CMU/MPPI、Gazebo/PX4、独立 FAST-LIVO2），改动限定在模式装配、薄入口、构建边界与文档。
- `tools/run.sh` 统一三模式；缺地图、未支持的模式与环境都会明确报错，不静默切换控制链。
- `firmware/tr800_f407` 独立构建（`COLCON_IGNORE`），两条线仅有 README 差异。
- 验收记录：版本组织与入口合同 7/7 通过；升级线 24 项 pytest、16 项入口分派检查通过；两线文档本地链接检查通过。这些结论覆盖的是仓库组织与装配合同，不代表编译或实车通过。

## 下一步（按优先级）

### P0 构建与冒烟

- 在 Ubuntu 20.04 + Noetic 执行 `bash tools/build-ros1.sh`，记录依赖缺失与补丁需求。
- 依次启动 `mapping`、`localization`、`navigation`，确认节点、TF 与话题符合 [architecture.md](architecture.md)。
- 验收标准：构建零错误；三模式 launch 无异常退出；无硬件时用录包或空地图完成定位链路冒烟。

### P0 固件复验

- 按 [固件 README](../firmware/tr800_f407/README.md) 构建、烧录，用 `tr800_serial_analyzer.py` 抓取遥测。
- 验收标准：`elf/hex/bin` 生成；OpenOCD 烧录成功；遥测 24 字节、命令 11 字节、帧头 0x7B / 帧尾 0x7D 正确。

### P1 标定与地图

- 雷达 JSON、安装外参、IMU 方向、轮距与速度限制按实车填写。
- 采集一张场地 PCD，验证 `localization` 的重复定位与静止漂移。
- 验收标准：初始定位可复现；静止漂移与重定位误差有数值记录。

### P1 导航

- 按场地调整 MoveBase3D 的膨胀、坡度上限、速度与局部控制参数。
- 验收标准：单点、多点、遥控接管与急停各有一轮记录。

### P2 升级线

- 接入升级版 PCD 定位；补齐 ROS 1 仿真适配的评估结论。
- 通用 hardware profile 的纯建图补齐标定配置。
- 重跑仿真矩阵前先处理近场观测覆盖与数据新鲜度问题，保留历史失败记录。
- 为 CMU local Path 增加显式任务身份，收紧陈旧输入防护。
- 编码器第 2 路闭环稳定性复测。

## 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 没有 CI | 回归全靠手工，容易漏 | 每次改动至少跑构建、三模式冒烟与 `run.sh --help` |
| 构建未复现 | 交接后第一步就可能失败 | 把 P0 作为接收方的第一项任务 |
| 地图与录包不入库 | 新环境没有可用地图 | 交接时单独交付数据，并记录来源与坐标系 |
| 串口协议跨三处 | 只改一端会导致车不动或遥测错位 | 改动清单同时列出固件与两条线的驱动 |
| 升级线仿真既有失败 | 容易被误读为“仿真可用” | 保留失败记录，不删除证据，也不放宽阈值 |
| 审计材料只在本地 | 删除后无法回溯 | 归档提交与 worktree 先确认再清理 |
