# TR800 通信协议

本文档只描述当前 TR800 第一阶段主线实际涉及的通信协议。

目标不是设计新协议，而是把**当前源码已经实现**的协议格式、编译开关差异、字段语义和已知不确定项写清楚，避免调试时把推断当事实。

## 1. 当前编译配置

以下内容以当前源码中的编译开关为准：

- `IBUS_EN = 1`：`BALANCE/robot_select_init.h`
- `SBUS_EN = 0`：`BALANCE/robot_select_init.h`
- `PROTOCOL_25 = 0`：`BALANCE/robot_select_init.h`
- `TR800_MOTOR_TELEMETRY_DEBUG = 0`：`BALANCE/robot_select_init.h`
- `TR800_CONTROL_TELEMETRY_DEBUG = 1`：`BALANCE/robot_select_init.h`
- `TR800_RC_TELEMETRY_DEBUG = 0`：`BALANCE/robot_select_init.h`
- `TR800_OPEN_LOOP_PWM_TEST = 0`：`BALANCE/robot_select_init.h`
- `MAVLINK = 0`：`BALANCE/robot_select_init.h`

这意味着：

1. 当前主线遥控输入使用 **IBUS**，`SBUS` 代码保留但未启用。
2. 当前 UART4 遥测帧长度是 **24 字节**，不是 25 字节。
3. 当前 UART4 遥测帧中的 `8..19` 字节**不是正常 IMU 遥测**，而是三页控制链诊断；`diag_0` 表示页号。

## 2. 协议总览

| 协议 | 方向 | 当前状态 | 代码位置 |
|---|---|---|---|
| UART4 控制帧 | 上位机 -> TR800 | 启用 | `HARDWARE/usartx.c:491-517` |
| UART4 遥测帧 | TR800 -> 上位机 | 启用 | `HARDWARE/usartx.c:633-714` |
| USART2 IBUS | 遥控器 -> TR800 | 启用 | `HARDWARE/usartx.c:195-268`、`920-1100` |
| USART2 SBUS | 遥控器 -> TR800 | 保留但未启用 | `HARDWARE/usartx.c:1320-1485` |
| USART3 MAVLink | TR800 -> 外部 | 当前未启用 | `HARDWARE/usartx.c:717-818` |

## 3. UART4 控制帧

### 3.1 当前事实

UART4 控制帧由 `UART4_IRQHandler()` 接收：`HARDWARE/usartx.c:491-517`

当前固定长度：

- `11 bytes`

帧头帧尾：

- `FRAME_HEADER = 0x7B`
- `FRAME_TAIL = 0x7D`

校验方式：

- `buffer[9] = XOR(buffer[0..8])`
- 实现位置：`HARDWARE/usartx.c:843-856`

控制量解析：

- `X = bytes[3:4]`
- `Y = bytes[5:6]`
- `Z = bytes[7:8]`
- 解析函数：`XYZ_Target_Speed_transition()`，`HARDWARE/usartx.c:859-867`

单位：

- 发送端按 `value * 1000` 后发出 `int16`
- 接收端还原为 `m/s` 或 `rad/s` 量纲的浮点值

### 3.2 当前字节布局

| 字节偏移 | 名称 | 类型 | 说明 |
|---|---|---|---|
| `0` | `header` | `u8` | 固定 `0x7B` |
| `1` | `reserved_1` | `u8` | 当前接收代码未使用 |
| `2` | `reserved_2` | `u8` | 当前接收代码未使用 |
| `3..4` | `x_cmd` | `int16_be` | `X` 方向命令，发送前乘 1000 |
| `5..6` | `y_cmd` | `int16_be` | `Y` 方向命令，发送前乘 1000 |
| `7..8` | `z_cmd` | `int16_be` | `Z` 方向命令，发送前乘 1000 |
| `9` | `checksum` | `u8` | `XOR(bytes[0..8])` |
| `10` | `tail` | `u8` | 固定 `0x7D` |

### 3.3 上位机工具现有实现

`tools/tr800_serial_analyzer.py` 当前构造控制帧方式：

- `frame[0] = 0x7B`
- `frame[1] = 0`
- `frame[2] = 0`
- `frame[3:5] = X`
- `frame[5:7] = Y`
- `frame[7:9] = Z`
- `frame[9] = XOR(frame[0..8])`
- `frame[10] = 0x7D`

与固件接收逻辑一致。

### 3.4 已知限制

事实：

- 当前 ISR 在中断里做收帧、校验和速度解码，再调用 `tr800_runtime_note_serial_cmd(X, Y, Z, now)`。命令的模式选择与生效路径属于运行状态机，不由帧格式定义。

未知：

- `reserved_1`、`reserved_2` 是否历史上有预留语义，当前源码中看不到消费逻辑。

## 4. UART4 遥测帧

### 4.1 当前事实

当前遥测打包入口：

- `data_transition()`：`HARDWARE/usartx.c`

当前发送任务：

- `data_task()`：40Hz，`HARDWARE/usartx.c`

当前发送长度：

- `24 bytes`

原因：

- `PROTOCOL_25 = 0`

帧头帧尾：

- `FRAME_HEADER = 0x7B`
- `FRAME_TAIL = 0x7D`

校验方式：

- `buffer[22] = XOR(buffer[0..21])`

### 4.2 当前字节布局（源码默认配置）

| 字节偏移 | 名称 | 类型 | 说明 |
|---|---|---|---|
| `0` | `header` | `u8` | 固定 `0x7B` |
| `1` | `flag_stop` | `u8` | 当前 `Flag_Stop` |
| `2..3` | `x_speed` | `int16_be` | `((A.Encoder + B.Encoder)/2) * 1000` |
| `4..5` | `y_speed` | `int16_be` | 当前固定 `0` |
| `6..7` | `z_speed` | `int16_be` | `((B.Encoder - A.Encoder)/Wheel_spacing) * 1000` |
| `8..9` | `diag_0` | `int16_be` | 页号 `1/2/3`，按帧循环 |
| `10..11` | `diag_1` | `int16_be` | 按页解释，见下表 |
| `12..13` | `diag_2` | `int16_be` | 按页解释，见下表 |
| `14..15` | `diag_3` | `int16_be` | 按页解释，见下表 |
| `16..17` | `diag_4` | `int16_be` | 按页解释，见下表 |
| `18..19` | `diag_5` | `int16_be` | 按页解释，见下表 |
| `20..21` | `voltage_mv` | `uint16_be` | `Voltage * 1000` |
| `22` | `checksum` | `u8` | `XOR(bytes[0..21])` |
| `23` | `tail` | `u8` | 固定 `0x7D` |

### 4.3 重要说明：当前不是正常 IMU 遥测

由于当前编译开关为：

- `TR800_CONTROL_TELEMETRY_DEBUG = 1`

所以 `8..19` 字节字段不是正常 IMU 三轴加速度/角速度。

`data_transition()` 每次发送循环切换页号；各诊断值保持有符号 16 位整数，需要收窄的字段使用固件 `tr800_i16_limit_long()` 限幅。

| `diag_0` 页号 | `diag_1` | `diag_2` | `diag_3` | `diag_4` | `diag_5` |
|---|---|---|---|---|---|
| `1` 遥控输入 | `RC_LX` | `RC_LY` | `RC_RX` | `RC_RY` | `RC_Speed` |
| `2` 命令与目标 | `Move_X * 1000` | `Move_Z * 1000` | `MOTOR_A.Target * 1000` | `MOTOR_B.Target * 1000` | 运行状态编码 |
| `3` 闭环与输出 | `MOTOR_A.Encoder * 1000` | `MOTOR_B.Encoder * 1000` | `MOTOR_A.Motor_Pwm` | `MOTOR_B.Motor_Pwm` | `tr800_runtime_get_fault_flags()` |

状态编码规则：

```text
status_code = system_state * 100 + requested_mode * 10 + active_mode
```

### 4.4 关闭全部诊断宏时的差异

只有 `TR800_OPEN_LOOP_PWM_TEST`、`TR800_MOTOR_TELEMETRY_DEBUG`、`TR800_CONTROL_TELEMETRY_DEBUG` 与 `TR800_RC_TELEMETRY_DEBUG` 全部为 `0` 时，才进入普通 IMU 分支：

- `8..13` 恢复为加速度计三轴
- `14..19` 恢复为角速度计三轴

这不是当前源码的默认配置。两线 ROS 驱动本轮统一停用串口 IMU，即使以后关闭固件诊断宏，也不会自动恢复 IMU 换算或发布；若需要该能力，应重新明确接口用途。

### 4.5 上位机工具当前解释

`tools/tr800_serial_analyzer.py` 使用原始 `diag_0..diag_5` 字段。当前固件需传 `--diag-control`，按页号显示遥控输入、命令/模式、编码器/PWM/故障；不传该选项时工具保留旧的电机诊断显示方式。

```bash
python tools/tr800_serial_analyzer.py --port COM4 --diag-control
```

设备名按现场修改。工具的 24 字节组帧、异或校验、轮速和电压解析保持原样。

### 4.6 ROS 驱动的消费边界

- main 驱动保留 `8..19` 原始字节，不将其写入 IMU 数据或姿态解算器；只发布 `/odom` 与 `/PowerVoltage`。
- upgrade/ros2 驱动原样保存六个诊断值到 `Telemetry.diagnostics`，不做 IMU 比例换算或姿态解算，也不发布 `imu`／`/chassis/imu`。
- FAST-LIO 的惯性源仍为 Livox：main 使用 `/livox/imu`，升级硬件整车映射为 `/sensors/imu/data`。底盘里程计的航向仍由轮速积分，不来自这些诊断值。

## 5. USART2 IBUS 协议

### 5.1 当前状态

当前编译配置：

- `IBUS_EN = 1`
- `SBUS_EN = 0`

因此实际遥控输入协议为 **FlySky IBUS**。

### 5.2 当前解析逻辑

解析位置：

- `USART2_IRQHandler()`：`HARDWARE/usartx.c:195-268`

协议状态机：

- `GET_LENGTH`
- `GET_DATA`
- `GET_CHKSUML`
- `GET_CHKSUMH`
- `DISCARD`

关键常量：

- `PROTOCOL_LENGTH = 0x20`
- `PROTOCOL_OVERHEAD = 3`
- `PROTOCOL_CHANNELS = 10`
- `PROTOCOL_COMMAND40 = 0x40`

当前处理规则：

1. 首字节为长度
2. `buffer[0]` 应为命令字 `0x40`
3. 提取 `10` 个通道
4. 校验通过后更新时间戳 `tr800_runtime_note_rc_rx(now)`

### 5.3 当前通道映射

`RC_Read()` 当前映射为：`HARDWARE/usartx.c:998-1007`

| IBUS 通道 | 当前变量 |
|---|---|
| `0` | `RC_RY` |
| `1` | `RC_LX` |
| `2` | `RC_RX` |
| `3` | `RC_LY` |
| `4` | `RC_power` |
| `6` | `RC_Speed` |
| `8/9` | `RC_Bias`（仅前/后调试模式） |

并且：

- 若不在前后调试模式，`RC_pid = RC_power`

当前模式选择阈值：

- `TR800_RC_MODE_SELECT_HIGH = 1700`
- 使用点：`HARDWARE/usartx.c:1537-1562`

### 5.4 当前数值范围

由于 `IBUS_EN = 1`，当前定义为：

- `RC_LOW = 1000`
- `RC_MID = 1500`
- `RC_HIG = 2000`
- `RC_ACT = 100`

### 5.5 已知问题

事实：

- 当前 IBUS 中断解析后，会更新时间戳和通道缓存。
- `RC_task()` 后续又根据这些通道直接请求模式，并通过 `rc_loop_control()` 写入 `Move_X/Z`。

推断：

- 协议输入本身没有问题，主要问题在于“解析结果被谁消费、如何生效”。

## 6. USART2 SBUS 协议

### 6.1 当前状态

当前编译配置：

- `SBUS_EN = 0`

因此 SBUS 相关路径目前只是保留代码，不是当前主线协议。

### 6.2 代码中保留的能力

当前仍保留：

- `sbus_begin()`
- `FeedLine()`
- `UpdateChannels()`
- `UpdateServos()`

以及 `FUTABA_SBUS` 数据结构：`HARDWARE/usartx.h`

### 6.3 说明

第一阶段不应以 SBUS 作为协议文档主路径，也不应围绕它继续扩展功能。  
若后续重新启用 SBUS，需要单独做一次“当前编译配置”核对。

## 7. MAVLink 串口发送

当前状态：

- `MAVLINK = 0`

因此 `USART3_SEND()` 虽有实现，但不是当前主线路径。

注意事项：

- 其内部是逐字节忙等发送
- 若后续重新启用，需要纳入“阻塞发送隔离”治理范围

## 8. 已知正确项 / 推断项 / 未知项

### 8.1 已知正确项

- UART4 控制帧长度是 `11 bytes`
- UART4 遥测帧长度是 `24 bytes`
- 当前主线 RC 协议是 `IBUS`
- 当前遥测调试模式是 `TR800_CONTROL_TELEMETRY_DEBUG=1`，电机、RC 与开环调试宏均关闭
- UART4 控制帧和遥测帧都使用 XOR 校验

### 8.2 推断项

- 控制帧 `byte1/byte2` 当前属于保留字段，没有生效语义
- `tools/tr800_serial_analyzer.py` 的显示模式需要与固件配置匹配；当前使用 `--diag-control`，不能仅凭诊断值猜测模式

### 8.3 未知项

- 历史版本是否曾给 `byte1/byte2` 定义过业务语义
- 现场已烧录固件的编译开关，应以实际烧录版本为准

## 9. 对实施的直接要求

本协议文档直接服务第一阶段改造，要求如下：

1. 不修改 UART4 控制帧和当前 24 字节遥测帧的**对外格式**
2. 可以修改 UART4 控制帧的**生效路径**
3. 后续若修改遥测帧 `8..19` 字节语义，必须同步更新本文件和上位机工具；当前 ROS 驱动不把该段作为 IMU
4. `IBUS` 当前为主线，`SBUS` 不进入第一阶段必修项
