# TR800 外部参考代码摘录

本目录只保留对 TR800 第一阶段修复有直接帮助的代码片段和调度说明。

目标不是照搬外部仓库，而是收敛出三类可复用经验：

1. 任务创建与周期设计
2. 串口/遥控输入路径的轻 ISR 设计
3. 在线/离线与控制归零的归属方式

## 使用边界

- 这里只摘录关键骨架，不复制整仓。
- 这里只服务 `SERIAL + RC` 两个控制源，不扩展到云台、裁判系统、上位机整套通信。
- 摘录代码仅作为结构参考；真正并入 TR800 前仍要按当前工程风格重写。

## 目录说明

- `TR800_调度建议.md`
  - 结合 TR800 当前任务结构给出的最小调度改造建议。
- `basic_framework/`
  - 值得学的模块边界、USART 回调收口、遥控快照和离线处理。
- `rm_examples/`
  - 值得学的最小任务优先级示例、遥控 DMA/IDLE 接收示例。
- `roborts_fw/`
  - 值得学的在线/离线钩子和控制归零方式。

## 当前判断

事实：

- TR800 当前 `Balance_task` 已经是 100Hz 主控制环：`BALANCE/balance.c:241-276`
- `RC_task` 仍在 50/80Hz 周期里直接请求模式并调用 `rc_loop_control()`：`HARDWARE/usartx.c:1539-1578`
- `UART4_IRQHandler()` 仍直接写 `Move_X/Y/Z` 与模式：`HARDWARE/usartx.c:491-517`

推断：

- TR800 不需要上大框架，也不需要先引入队列系统。
- 当前最该借鉴的是“全局快照 + 单一写者 + 轻 ISR”，不是“复杂消息总线”。

未知：

- 若后续你们要把 IMU、裁判系统、CAN 协议都重新拉回主线，当前目录中的轻量调度方案需要再扩一层。
