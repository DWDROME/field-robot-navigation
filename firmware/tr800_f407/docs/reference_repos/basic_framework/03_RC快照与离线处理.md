# basic_framework - RC 快照与离线处理

来源：

- 仓库：`HNUYueLuRM/basic_framework`
- 文件：`modules/remote/remote_control.c`

## 摘录代码

```c
static RC_ctrl_t rc_ctrl[2];
static USARTInstance *rc_usart_instance;
static DaemonInstance *rc_daemon_instance;

static void RemoteControlRxCallback()
{
    DaemonReload(rc_daemon_instance);
    sbus_to_rc(rc_usart_instance->recv_buff);
}

static void RCLostCallback(void *id)
{
    memset(rc_ctrl, 0, sizeof(rc_ctrl));
    USARTServiceInit(rc_usart_instance);
}

RC_ctrl_t *RemoteControlInit(UART_HandleTypeDef *rc_usart_handle)
{
    conf.module_callback = RemoteControlRxCallback;
    rc_usart_instance = USARTRegister(&conf);
    rc_daemon_instance = DaemonRegister(&daemon_conf);
    return rc_ctrl;
}
```

## 值得学的点

1. 遥控输入有独立快照，不直接碰运动输出。
2. 接收回调只做“喂狗 + 解析”。
3. 离线时明确清零并重启接收。

## 对 TR800 的直接启发

- `RC_task` 应该只更新 `g_rc_cmd`，而不是直接写 `Move_X/Y/Z`。
- `tr800_runtime_rc_alive()` 的概念是对的，但还缺一个真正的 RC 命令快照层。
- RC 失联后的动作要明确：清 RC 快照、标记无效、等待主环仲裁归零。

## 不要照搬的点

- 不需要立刻引入完整 daemon 模块。
- 对 TR800 来说，先有 `rx_ms + valid` 就已经足够。
