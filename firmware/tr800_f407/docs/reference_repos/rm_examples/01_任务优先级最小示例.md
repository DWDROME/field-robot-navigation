# Development-Board-C-Examples - 任务优先级最小示例

来源：

- 仓库：`RoboMaster/Development-Board-C-Examples`
- 文件：`17.chassis_task/Src/freertos.c`

## 摘录代码

```c
osThreadDef(cali, calibrate_task, osPriorityNormal, 0, 512);
calibrate_tast_handle = osThreadCreate(osThread(cali), NULL);

osThreadDef(ChassisTask, chassis_task, osPriorityAboveNormal, 0, 512);
chassisTaskHandle = osThreadCreate(osThread(ChassisTask), NULL);

osThreadDef(DETECT, detect_task, osPriorityNormal, 0, 256);
detect_handle = osThreadCreate(osThread(DETECT), NULL);

osThreadDef(imuTask, INS_task, osPriorityRealtime, 0, 1024);
imuTaskHandle = osThreadCreate(osThread(imuTask), NULL);
```

## 值得学的点

1. 控制任务优先级高于普通检测与显示任务。
2. 采样敏感任务和控制任务优先级区分清楚。
3. 任务数量不多，但角色清晰。

## 对 TR800 的直接启发

- 你现在把 `RC_task` 放在 `Balance_task` 之上，不合理。
- 若确实要保证某个采样任务实时性，可以让它和主控制同级或略低，但不该让遥控输入高于运动输出。

## 不要照搬的点

- 不要机械模仿 `Realtime`、`AboveNormal` 这些名字。
- 真正重要的是：谁是最终执行器，谁就必须拥有更稳定的调度地位。
